# Implementation Plan

## Decisions carried into implementation

- Keep bundle format 3. Current writers will emit one image whose sole target is one family (`c6`, `s3`, or `p4`); existing readers will continue accepting historical multi-target bundles.
- Use `firmware-releases/manifest.json` as the canonical release catalog. It will list exactly three families and, for each, the latest SemVer, relative artifact path, SHA-256, byte size, chip token, accepted runtime profile tokens, flash/partition compatibility, and identity evidence required for safe selection.
- Build one S3 binary using the 8 MB common-denominator flash layout and runtime profile selection. Profile-only payloads that cannot fit every supported S3 device, including the 16 MB Doom WAD partition, will not be part of the canonical S3 release artifact; Doom source may remain as a developer-only/profile-gated feature but must not create another release family.
- Keep `PlatformConfig`, `PanelConfig`, and carrier `Config` separation. Internal carrier/profile names such as `P4_4B` and `st7703-4b` may remain, but firmware target metadata, CLI choices, release filenames, app resources, and documentation must expose only `c6`, `s3`, and `p4` as release families.
